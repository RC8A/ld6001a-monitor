# Изменения проекта

Основная ветка — `main`. Внешние изменения принимаются через pull request, а не прямым push в `main`.

1. Создайте короткую ветку `fix/...`, `feature/...` или `docs/...`. Изменения агента могут использовать `codex/...`.
2. Один PR решает одну понятную задачу. Объясните исходную проблему, результат и проверку.
3. Перед PR запустите `Source/Build.ps1 -NoLaunch`. Для изменений интерфейса приложите изображения из `Source/Previews` и проверьте их глазами.
4. Изменения протокола подтверждайте обезличенным примером пакета или ссылкой на документацию. Не прикладывайте реальные полные журналы по умолчанию.
5. Сохраняйте совместимость `data/settings.ini`, формата CSV и безопасное поведение подключения: только чтение до действий пользователя.
6. Автор проекта проверяет PR и принимает его через **Squash and merge**. После объединения ветку можно удалить. История main содержит одно содержательное изменение на PR.

Коммиты: `fix: ...`, `feat: ...`, `docs: ...`, `chore: ...`. Императивный заголовок должен объяснять результат. Не добавляйте EXE, ZIP, журналы, настройки, токены, архивы старых версий или программы производителя.

Используйте `git commit -s`: подпись Signed-off-by означает, что у вас есть права передать этот вклад. Это не передача авторства правообладателю проекта. Отправляя PR, вы соглашаетесь предоставить свой вклад под PolyForm Noncommercial 1.0.0 на тех же условиях, что проект. Для изменения лицензии при нескольких правообладателях понадобится учитывать права участников.

Для закрытого репозитория доступ даётся только выбранным участникам. Рекомендуемые правила main: PR, успешный CI, рассмотренные обсуждения, запрет force push и удаления. Доступность принудительной защиты приватных веток зависит от тарифа GitHub; в одиночном проекте не включайте требование чужого одобрения, если другого рецензента нет.
